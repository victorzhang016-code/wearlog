# Quick Outfit 推荐重构设计

**日期**：2026-08-16  
**状态**：Victor 已确认方向，进入实现

## 一、问题

当前 Quick Outfit 页面把完整搭配、替换关系、单品清单和审美解释同时展开，用户第一眼无法判断应该看什么。当前推荐也主要依赖“把当前单品塞进已有 Best Match”，当一件单品没有合适的历史搭配骨架时，很快会耗尽候选。

这次重构要同时解决两个问题：

1. 用一条清晰的信息链呈现推荐：当前单品 → 来源搭配 → 替换位置 → 成立原因。
2. 在保留已有 Best Match 替换路径的同时，增加完整的“单品直搭”路径，寻找此前没有完整出现、但基于审美证据可以成立的新组合。

## 二、产品设计

### 2.1 主推荐

页面首屏只聚焦一套推荐。首屏信息按以下顺序展示：

- **当前单品**：图片与名称；
- **来源**：某套 Best Match，或“单品直搭”；
- **动作**：替换哪个位置，以及被替换的原单品；
- **原因**：一句来自审美分析的解释，说明色彩、轮廓、材质、正式度、视觉重量或设计焦点中的成立条件。

完整单品预览保留为紧凑的视觉辅助，不再用多列信息卡抢占主叙事。详细证据可以折叠查看。

主推荐可以连续翻看，候选耗尽后明确显示“当前没有更多有依据的新组合”，不伪造无限推荐。

### 2.2 两条生成路径

#### 路径 A：Best Match 单槽位替换

- 当前单品保留在结果中；
- 从成熟 Best Match 中替换一个位置；
- 完整组合此前没有在 Best Match 或变体中出现；
- 候选与被替换单品在品类和功能位置上兼容；
- 推荐理由至少包含一个结构/风格信号和一个整套关系信号；
- 用户拒绝后，精确的“核心搭配 + 槽位 + 候选单品”进入反例集合。

#### 路径 B：完整单品直搭

单品直搭不是只给当前单品配一件孤立单品。它必须形成一套基础穿法：

- 基础部件齐全：外衣、内搭、下装、鞋子；
- 当前数据模型将外衣和内搭统一放在 `tops` 槽位，因此保留来源 Best Match 中已有的多个 `tops` 位置，不自行虚构不存在的部件；
- 如果衣柜中没有足够的基础部件，宁可不给出直搭结果；
- 配饰最多一个，只在已有审美关系足够明确时作为点睛项加入；
- 组合此前没有完整出现；
- 组合中的主要单品不能在同一位置重复堆叠；
- 仍需有可追溯的色彩、结构、材质、比例或风格关系，并生成一句话理由。

单品直搭可以借用某套 Best Match 的成熟基础结构作为模板，但产品表达上标记为“单品直搭”，避免让用户误解为已经被保存过的 Best Match。

推荐排序优先考虑：已验证替换关系、原则支持强度、基础部件完整度、结构与色彩关系、历史评分和稳定 ID。精确历史组合和用户拒绝的组合先过滤。

### 2.3 参考推荐

主推荐下面保留最多三张轻量参考：

1. 原始、最正统的 Best Match；
2. 一个轻微变体；
3. 一个更靠边的单槽位变体。

参考只承担“让我回想起我已经穿过什么”的作用。每套参考最多保留一个鞋位和一个配饰位，不把包、首饰等配饰堆成新的视觉中心。

### 2.4 反馈与训练

- `合适`：记录正向反馈，不要求输入文字；
- `不太合适`：必须填写原因，记录为精确反例；
- `换下一套`：只记录跳过，不形成负面判断；
- 反馈立即影响本地下一次确定性生成；
- 已登录用户同时写入服务端推荐事件，保留推荐快照、原因和版本信息，供后续服务端分析使用。

## 三、技术边界

- 不引入 Kimi 直接自由生成整套搭配；
- 推荐生成继续使用现有 `AnalysisRun`、`OutfitCaseGraph`、`CombinationOpportunity`、颜色和设计证据；
- 新增的直搭候选必须是确定性的，输入相同则结果和排序稳定；
- 不改变 Best Match 的存储模型；
- 不把推荐结果直接写成已确认 Best Match；
- 不把配饰数量作为填满卡片的手段。

## 四、验收标准

- 用户首屏能在几秒内读出当前单品、来源、替换位置和一句理由；
- 单槽位替换和单品直搭两条路径都能产生推荐；
- 直搭缺少外衣/内搭/下装/鞋等基础部件时不输出不完整套装；
- 新组合不重复历史完整组合，精确拒绝后不再出现；
- 一套最多一个配饰，参考卡不堆叠同一位置；
- 合适、不合适、跳过三类反馈语义分离，并能进入下一轮确定性分析；
- 原有审美测试、推荐测试、lint 和 build 全部通过。
