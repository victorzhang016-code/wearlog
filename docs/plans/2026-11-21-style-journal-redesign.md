# 我的风格志：结果页与个人审美模型

日期：2026-11-21。范围：本地实现与验收，未部署 Production。

## 用户任务与验收

Victor 已明确：分析台要从用户想得到的结果出发，图像主导，主要回答自己的颜色怎么归类、搭配里有什么风格联系、为什么、下一次可以怎样穿，以及同类单品怎样替换。保留衣LOG 首页与 Best Match 的材质、字体、吊牌和色卡语言。

使用场景：已有衣物或 Best Match 的用户想回看自己的选择，或找下一次搭配的依据。旧页面的替代方式是逐个读内部原则、案例、校准和字段，阅读成本过高。本次取消这套后台式导航。

- 两个阅读入口：我的色卡 / 我的穿搭，沿用 `/aesthetic`。
- 色卡默认看主色，也能切换全部、辅色、点缀色。按感知色系分组，保留实际 RGB；点击色系看对应单品与已有搭配。
- 穿搭以真实衣物拼贴为主，旁边给短结论、可参考的选择、同套色卡；可切换代表案例。
- 数据中学到的关联与原有搭配思路并存。统计分母、总体对照、例外与原文按需展开。
- 替换限于当前 Best Match 中仍存在的同类变体。可选择品类、替换对、原搭配，切换换前/换后。配饰必须同子类型。
- 空衣柜、未确认颜色、读取失败、缺图、无搭配、无同类替换均有可操作状态。
- 导航、主页入口与页标题统一为“我的风格志”。

无新增使用率或效果目标。当前验收以能完成上述任务、375/390px 与桌面无横向溢出、来源可追溯为准；后续用真实反馈建立基线。

## 视觉决策

完全沿用设计系统：linen `#D2CCBE`、tag `#FDFCF5`、ink `#1C1C1A`、graphite `#6B6A65`、string `#8B7355`。正文与中文标题使用现有 Story 字体，英文辅助标题使用 Display，少量档案元信息使用 Tag。

色卡章节的识别点是已有的实体色卡扇与可翻阅的色卡列；穿搭章节是左右相邻的衣物拼贴与短解释，手机顺序为图、结论、依据。避免顶部 KPI、工具流程图、覆盖率大卡、技术版本号和校准表格。

## 基座审查：现状与问题

旧基座并非只有文本：它已经计算 RGB→Lab/OKLCH、确认字段、槽位、变体和搭配关系。但原则文案来自固定的机制词典；重复命中某类关系后套入预写句子。这能辅助解释，不能独立证明系统学到了个人偏好。

本轮确认的问题：

1. 旧留出验证从全量 `SubstitutionContract` 取变体，包含正在留出的搭配，存在答案泄漏。已改成只读取训练搭配里的同槽位变体，且只使用 confirmed 特征。重算引擎升级为 v3.6 / v4.2，历史运行文件保留。
2. 旧规则级验证按涉及的槽位聚合恢复结果，并非单独移除或重算该条规则；不能解释为该句文案已得到因果验证。新的用户页面不把这些恢复指标写成“已证明”。
3. 原产品页通过 `buildLiveAestheticRun` 读全局浏览器实验台状态，有混入其他账号本地记录的风险。新产品页只从登录账号的数据构建当前特征；不再自动写风格志云表。
4. 旧云快照可能落后于当前衣柜。色卡和新关联使用当前确认字段；旧案例检查当前主件，替换检查当前真实槽位，已删除记录不继续推荐。

## 调研判断

阅读重点包含方法、训练数据和评估设置，不以摘要中的效果数字作为衣LOG的预期。

- [Vasileva et al., ECCV 2018，Type-Aware Compatibility](https://arxiv.org/html/1803.09196v2)：区分同类型相似与跨类型兼容，并使用按单品隔离的数据划分。这支持衣LOG把替换与整套关系分别建模。其大规模预训练数据条件与个人衣柜不同，不能直接复用论文效果。
- [Lu et al., CVPR 2021，Learnable Anchors](https://openaccess.thecvf.com/content/CVPR2021/papers/Lu_Personalized_Outfit_Recommendation_With_Learnable_Anchors_CVPR_2021_paper.pdf)：将用户偏好表示为多个可学习的风格锚点，新用户可从共享锚点中选择。它依赖跨用户训练，当前两个账号的衣LOG不具备同样条件。可以借鉴多种风格并存的表示，暂不训练同规模神经模型。[作者代码](https://github.com/lzcn/LPAE-Net)
- [Celikik et al.，Outfit Generation and Recommendation: An Experimental Study](https://arxiv.org/pdf/2211.16353)：比较通用兼容与用户条件化推荐，也指出填空成绩和最终生成质量并非同一件事。衣LOG必须同时检查候选可用性、个人偏好与真实穿后反馈。

推荐路线是“已确认视觉事实 + 个人案例记忆 + 可检验的条件关联 + 有边界的替换”。大模型可以帮助读图和理解原文，但正式结论和推荐要由可复算的数据结构支持。当前不引入外部训练集或发送私有衣柜给外部模型。

## 已实施的个人关联模型

代码：`src/lib/personalStyleModel.ts`，版本 `wearlog-personal-context-v1`。

输入只包含当前 confirmed 的颜色、廓形、材质、图案、风格特征，以及本人保存的搭配槽位。故事、评分和单品 ID 不作为风格特征；名称仅用于显示。第一件上装作为当前搭配核心，是现行产品约定，不是模型发现。

模型学习 `核心上装特征 → 某个支持位置的特征`。每套搭配计一次，重复主件/多标签不反复抬高样本量。目标维度缺失视为未知。对照来自本人全部有该维度记录的同槽位搭配，不把拥有某件衣服等同喜欢某种搭法。

计算保留支持数、条件样本数、总体基线、不同核心数、例外搭配和来源 ID。用 `(支持数 + 4 × 总体基线) / (条件样本数 + 4)` 做小样本收缩。至少 3 套、2 件不同核心、收缩后高出基线 0.08 才进入候选。这些阈值是工程先验，并未被验证为最优；输出始终叫关联观察，不叫稳定审美定律。它不证明因果，也未控制季节、衣柜供给和标签相关性。

例如这份真实快照中，“简约”上装下选阔腿西装短裤为 4/6 套，总体同类选择为 6/43 套。这句话随真实配对改变而改变，不依赖故事的措辞。前端只选少量不同的观察，避免把 113 条候选全部堆出来。

## 两条探索路线与实验结果

输入：本地快照 `2026-08-03T16-03-04-528Z-4998E228F5DA.json`，101 件单品、43 套搭配。数字只适用于这份历史快照，不代表今日线上衣柜。

协议：按核心外衣整体留出，同一核心的所有搭配及变体都从训练移除；规则在每个训练折重新挖掘；共同使用当前衣柜同品类候选池；下装保留已知长短类型。评估下装和鞋 87 个位置，候选不超过 3 的位置不计。已确认单品视觉属性可用，这是固定衣柜中的搭配恢复，不是未知服装或跨用户泛化测试。

| 方法 | Top-3 找回主件或已存变体 | Top-3 只找回原主件 |
| --- | ---: | ---: |
| 本人高频单品基线 | 78/87 | 50/87 |
| 条件关联似然排序 | 74/87 | 40/87 |
| 相近核心案例检索 | 83/87 | 53/87 |

条件关联适合提供可读观察，目前不适合作为新推荐排序。案例检索使用确认特征的 IDF 加权 Jaccard 相似度，从训练搭配投票支持件；每个槽位的变体平分该案例权重，不因变体多而获得更多总票数。它初步优于基线，但主件恢复只多 3 次，且未做独立外部验证或显著性检验。此处不能声称已解决个性化推荐。

未选组合是未知，不作为用户不喜欢的负例。保留主件与允许变体两套指标，防止“变体很多所以容易命中”遮掩真正差异。

实验详细来源、分折 ID 和结果保存在 `.local-data/ui-review/personal-model-result.json`，不提交私人快照。模型代码包含可复用的 `evaluatePersonalStyleModel`；下一轮应锁定新数据作真正的未见测试集，增加季节与功能位置条件，再把案例检索接入现有整套配色/结构约束。没有通过约束的新组合不直接给用户。

### Kimi 实测与 DeepSeek 判断

实测日期：2026-11-21。仅使用 `.env.local` 的既有密钥，不把密钥写入报告。

- Kimi 文字请求与红/蓝测试图均返回 HTTP 200，图像左右颜色判断正确。现有本地密钥有效。
- 四类真实图片的初步探测均返回合法 JSON，其中三类品类一致；未带目标名称的领带人物照被判断为上装，说明多单品照片可能选错主体。它是小样本风险探测，不是准确率评测；正式单品识别请求携带单品名。随后针对同一张领带照片加入“当前目标：力量领带”的提示，返回合法 JSON，类别纠正为配饰（约 6.1 秒）；报告在 `.local-data/ai-evaluation/kimi-accessory-targeted.json`。这表明主体提示对整身照片有实际影响，仍不能推广为所有图片已准确。
